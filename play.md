# Silero TTS pipeline (`play.sh`)

Локальный конвейер: русский текст → нормализация для TTS → Silero v5 → WAV-фрагменты → воспроизведение.

Рабочая директория: каталог скрипта (`cd "$(dirname "$0")"`), обычно `/home/ant0m`. Запуск: `./play.sh`, `./play.sh 4` или `./play.sh 4 --no-play`. Без аргумента скорость `medium`.

Интерпретатор закреплён в `play.sh`: `$SILERO_PYTHON`, иначе `$HOME/.pyenv/versions/silero/bin/python` (pyenv env `silero`, CPython 3.10.13). Не использовать `silero2` и system python. `PYENV_VERSION` в интерактивной сессии больше не требуется.

---

## Быстрый старт

1. Положить исходный текст в `input.txt` (UTF-8).
2. Запустить `./play.sh` или `./play.sh N`, где N — скорость 1–5. Лишний аргумент — usage в stderr и `exit 1`. `-h` и `--help` — тот же usage (тоже в stderr) и `exit 0`.
3. Слушать concat через `ffplay`. Файлы остаются в `silero_output/out_NNNN.wav` (четыре цифры). Синтез пишется в `silero_output.new` и подменяет рабочий каталог только после успеха: упавший прогон оставляет прежние WAV нетронутыми. Перед `ffplay` первый и последний WAV проверяются `ffprobe`: на битом файле `ffplay` возвращает 0, так что без проверки молчаливая пустота выглядела бы успехом.
4. Только синтез, без проигрывания: `./play.sh --no-play` или `PLAY=0 ./play.sh`. Если `ffplay` нет или он упал, WAV всё равно остаются, код возврата синтеза при этом 0.
5. Флаги сверх скорости (все необязательные, поведение по умолчанию не меняют): `--voice baya`, `--device cpu`, `--log run.log` (копия вывода прогона в файл), `--resume` (не пересинтезировать уже готовые `out_NNNN.wav`). Подробности — шаг 3a и шаг 12 разбора `play.sh`.

Скорость речи (Silero SSML `prosody rate`):

| N | rate | смысл |
|---|---|---|
| 1 | `x-slow` | очень медленно |
| 2 | `slow` | медленно |
| 3 | `medium` | норма (по умолчанию) |
| 4 | `fast` | быстро |
| 5 | `x-fast` | очень быстро |

Чтобы только нормализовать текст, без синтеза:

```bash
~/.pyenv/versions/silero/bin/python txtproc.py
# пишет silero_input.txt
```

Чтобы только синтез (если `silero_input.txt` уже готов):

```bash
~/.pyenv/versions/silero/bin/python silero10.py      # medium
~/.pyenv/versions/silero/bin/python silero10.py 4    # fast
```

Регрессии нормализатора и нарезки (модель не грузится, сеть и GPU не нужны):

```bash
~/.pyenv/versions/silero/bin/python tests/test_normalize.py   # OK <N> cases, chunks, synthesis errors
```

Нарезка импортируется из `chunking.py` — он без `torch`, поэтому тесты не зависят от
модели; `render_sentences` по-прежнему приходит из `silero10.py` и проверяется заглушкой.
Чтение входа (нет файла, не UTF-8) вынесено в `textio.py` и проверяется тем же раннером:
сообщения и коды возврата — тоже контракт. Раздел «Ошибки входа» внутри разбора `play.sh`.

Установка с нуля (чистая машина, GPU): одна команда с `--extra-index-url` плюс системные
`ffmpeg` и `libsndfile1` — раздел «Установка с нуля» ниже.

## Поток данных

```
input.txt
    │
    ▼
txtproc.py          normalize_text()
    │
    ▼
silero_input.txt    текст словами; переводы строк абзацев сохранены
    │
    ▼
silero10.py         абзацы и [.?!] вне кавычек, склейка коротких,
                    дорезка длиннее 500 символов, apply_tts (SSML rate)
    │
    ▼
silero_output/out_0001.wav …
    │
    ▼
list.txt            ffmpeg concat demuxer
    │
    ▼
ffplay              воспроизведение и выход
```

`play.sh` передаёт в `silero10.py` только скорость `1`–`5`. Пути по умолчанию одинаковые, переопределяются переменными окружения (см. ниже).

|---|---|---|

| `tests/cases.txt` | пары «фраза → ожидание» | да, вместе с правкой нормализатора |

| `silero_output/` | WAV по фрагментам | генерируется |
| `silero_output.new/` | staging синтеза, живёт только время прогона | генерируется, при падении может остаться с частичными WAV |
| `list.txt` | concat-манифест | генерируется |
| `silero_output.old/` | временный снимок старого результата на время подмены | генерируется и удаляется в том же прогоне |
| `nomtext.py` | черновик препроцессора | нет, не в пайплайне, синтаксически сломан |
| `silero2.py` … `silero9.py` | старые прототипы TTS | нет, не вызываются |

## `play.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")"
# разбор: [1-5], --no-play / --play, --voice, --device, --log, --resume
# -h/--help — usage и exit 0; лишнее — usage и exit 1
# PLAY=0 тоже выключает ffplay
PY="${SILERO_PYTHON:-$HOME/.pyenv/versions/silero/bin/python}"
# нет исполняемого файла — сообщение и exit 1
stage="${SILERO_OUTPUT_DIR}.new"; stale="${SILERO_OUTPUT_DIR}.old"
rm -rf "$stage"; mkdir -p "$stage"     # рабочий каталог до успеха не трогаем
# --resume: готовые out_NNNN.wav из рабочего каталога — жёсткими ссылками в staging,
# silero10.py (SILERO_RESUME=1) их пропускает и синтезирует недостающие
"$PY" txtproc.py                        # нет входа / не UTF-8 — exit 1, прежние WAV целы
SILERO_OUTPUT_DIR="$stage" "$PY" silero10.py "$rate"   # код возврата решают set -e / rc
# ненулевой rc → прежнее содержимое SILERO_OUTPUT_DIR цело, staging с частичными wav остаётся
# предупреждение, если wav не out_NNNN.wav (проверяется в staging, путь печатается финальный)
# список собирается LC_ALL=C sort -V
# список — из staging, но с финальными путями; подмена каталога только после успеха
# --no-play / нет ffplay / ffplay упал: WAV уже готовы, exit 0
probe_first_last "$SILERO_LIST" || true   # ffprobe первого и последнего wav (D8), rc не меняет
ffplay -loglevel error -f concat -safe 0 "$SILERO_LIST" -autoexit
```

Первая строка — `#!/usr/bin/env bash`. `set -euo pipefail`: ненулевой код `txtproc.py` или `silero10.py` останавливает скрипт до `ffplay` (код возврата передаётся наружу: 1 и 2 соответственно). Ошибка синтеза (`exit 2`) до проигрывания не доходит. Подмена рабочего каталога — последние шаги перед `ffplay`: `mv` старого в `.old`, `mv` staging на его место, удаление `.old`. Провал последней команды возвращает `.old` на место и выходит с 1. Падение самого `ffplay` скрипт ловит отдельно и не маскирует под провал синтеза.

Шаги:

1. `cd` в каталог `play.sh`. Запуск из другого cwd всё равно читает `input.txt` рядом со скриптом.
2. Скорость — один аргумент `1`–`5`. Нет аргумента — `3` (`medium`). Иное значение, два числа или хвост (`./play.sh 3 extra`) — usage в stderr и `exit 1`. `-h` и `--help` печатают тот же usage (тоже в stderr, не в stdout) и выходят с `0`: текст назначения — не поток данных, его можно перенаправить только stderr. В Python уходит число, не имя `fast`.
3. `--no-play` или `PLAY=0` отключают `ffplay`. `--play` включает его обратно.
3a. Флаги с значением (`T14`): `--voice ГОЛОС`, `--device cuda|cpu`, `--log ФАЙЛ`. Каждый только пробрасывает окружение (`SILERO_VOICE`, `SILERO_DEVICE`) и не меняет поведение по умолчанию. Значение обязательно и не должно походить на другой флаг: `./play.sh --voice --no-play` — это ошибка (иначе голос стал бы «--no-play», ffplay молча выключился, а прогон выглядел успешным). `--device` принимает ровно `cuda` или `cpu`; список голосов совпадает с `silero10.py`. `--log` включается прямо на месте разбора аргумента (`exec > >(tee ФАЙЛ) 2>&1`) и требует tty на stdout: при перенаправленном stdout флаг отклоняется с `1`, потому что вывод прогона в терминале потерялся бы. Каталог лога обязан существовать — `play.sh` его не создаёт.
4. Берёт интерпретатор `silero`. Чужой `python` из `PATH` не используется.
5. Рабочий каталог до успеха не трогается: `rm -f out_*.wav` вынесен из начала прогона. Синтез пишется в staging `${SILERO_OUTPUT_DIR}.new`, который создаётся перед `silero10.py`. Старые WAV живут на месте, пока прогон не станет успешным.
6. `txtproc.py` читает `TTS_INPUT` (по умолчанию `input.txt`), пишет `SILERO_INPUT` (по умолчанию `silero_input.txt`). Скорость сюда не передаётся.
7. `silero10.py "$rate"` вызывается с `SILERO_OUTPUT_DIR=<staging>` и пишет `out_0001.wav`, `out_0002.wav`, … туда. Хотя бы одна ошибка модели — `exit 2`, склейка не начинается, а в stderr добавляется `Предыдущие файлы сохранены в <каталог> (синтез не удался)`. Если часть фрагментов успела записаться, staging остаётся и о нём сказано в stderr (`Частичные файлы синтеза: silero_output.new (N wav)`); пустой staging удаляется. Тот же текст и тот же код возврата даёт падение `txtproc.py` (нет входного файла, не UTF-8) — про синтез тогда ничего не пишется, но прежний результат тоже цел.
8. Файлы не по шаблону `out_NNNN.wav` (ровно 4 цифры) печатаются в stderr и в `list.txt` не попадают.
9. `list.txt` (`SILERO_LIST`) собирается `sort -V`, не лексикографическим glob. Имена берутся из staging, а в файл пишутся финальные пути (`silero_output/out_NNNN.wav`), иначе `ffplay` указал бы на каталог, которого после подмены нет. `list.txt` перезаписывается уже по готовому списку, до подмены каталога.
10. Нет wav — сообщение и `exit 1`. Синтез, который не дал ни одного файла (пустой `input.txt`), тоже сюда: staging удалён, прежний каталог цел.
11. `ffplay -loglevel error` играет склейку и выходит (`-autoexit`). Фильтров `atempo` нет. Нет `ffplay` или ненулевой код — предупреждение и `exit 0`: WAV уже лежат.
12. Перед `ffplay` — предпроверка `probe_first_last` (D8/T10): `ffprobe` проверяет первый и последний WAV из списка. На битом файле `ffplay` пишет `Impossible to open …` и **возвращает 0**, поэтому без проверки битая склейка неотличима от сыгранной. Результат — одна строка в stderr (`Предупреждение: silero_output/out_0001.wav не читается как аудио (ffprobe) — склейка может играть молча`) и **тот же код возврата, что был**: 0. Проверка не добавляет новых кодов выхода и не прерывает прогон: нет `ffprobe`, нет файла или пустой список — функция молча возвращает 0. Проверяются два файла, а не все: цель — поймать «склейка не играется целиком», а не инвентаризировать каталог на 658 файлов.

Переменные путей (дефолты в `play.sh`, их же читают оба Python-скрипта):

| Переменная | По умолчанию |
|---|---|
| `SILERO_PYTHON` | `~/.pyenv/versions/silero/bin/python` |
| `TTS_INPUT` | `input.txt` |
| `SILERO_INPUT` | `silero_input.txt` |
| `SILERO_OUTPUT_DIR` | `silero_output` |
| `SILERO_LIST` | `list.txt` |
| `SILERO_VOICE` | `aidar` (только `silero10.py`); `play.sh` — `--voice` |
| `SILERO_DEVICE` | пусто = `cuda`, если есть, иначе `cpu`; `play.sh` — `--device` |
| `SILERO_RESUME` | пусто; `1` — пропуск готовых `out_NNNN.wav`. Ставится флагом `--resume`, у `silero10.py` читается напрямую |
| `SILERO_HEADROOM_DB` | `-1` (только `silero10.py`) — запас по громкости; `0` выключает правку |
| `PLAY` | `1`; `0` — не играть |

У `play.sh` нет своих значений для `SILERO_VOICE`, `SILERO_DEVICE`, `SILERO_HEADROOM_DB`: флаги просто
перехватывают окружение, а остальное передаётся как есть. Поэтому `SILERO_HEADROOM_DB=0 ./play.sh`
работает, а вот `--voice` и `--device` у оболочки-вызова имеют смысл именно как флаги (переменная
окружения тоже сработает, но флаг заметнее в истории команд).

Ограничение нумерации: `out_0001`…`out_9999`. Пятый разряд и прочие wav в склейку не входят, о них есть предупреждение.

Внешняя зависимость оболочки для проигрывания: `ffplay` (ffmpeg). Для синтеза не обязательна.
Ещё одна внешняя библиотека — `libsndfile1`, её грузит `soundfile`; ставится через `apt-get`
(см. «Установка с нуля»). Синтез без неё не работает, воспроизведение — работает: `ffplay` WAV
читает сам.

### Ошибки входа

Чтением файлов занимается `textio.py`: `read_text_file(path)` бросает `InputError` с готовым
русским сообщением, а скрипты печатают его в stderr и выходят с `1`. Traceback на входных
ошибках — дефект (D6/T6), тесты проверяют отсутствие слова `Traceback` в stderr.

| Ситуация | Сообщение (stderr) | Код возврата |
|---|---|---|
| нет `TTS_INPUT` | `Нет входного файла: input.txt` (`txtproc.py`) | `1`, `silero_input.txt` не перезаписан |
| `input.txt` не в UTF-8 | `Файл input.txt не в UTF-8: байт ff в позиции 0, строка 1; нужен UTF-8, например: iconv -f WINDOWS-1251 -t UTF-8 input.txt` | `1`, выход не перезаписан |
| UTF-16 с BOM | то же, но хвост: `похоже на UTF-16 (BOM в начале файла), нужен UTF-8` | `1` |
| каталог вместо файла | `Это каталог, а не текстовый файл: путь` | `1` |
| нет прав | `Нет доступа к файлу: путь` | `1` |
| прочее `OSError` | `Не удалось прочитать путь: <strerror>` | `1` |
| пустой `input.txt` | `Пустой вход: input.txt, выход silero_input.txt будет пустым` | `0` — это не ошибка |
| нет `SILERO_INPUT` / он не в UTF-8 | те же тексты (`silero10.py`) | `1`, до `makedirs` и до загрузки модели |

BOM в начале входа допустим: файл читается как `utf-8-sig`, а выход `txtproc.py` пишется без BOM.

Для `play.sh` всё это обычные ненулевые коды возврата: рабочий каталог и `list.txt` целы, staging
пуст — в stderr добавляется `Предыдущие файлы сохранены в silero_output (синтез не удался)`.
Пустой вход — отдельная ветка: `txtproc.py` выходит 0, `silero10.py` даёт 0 фрагментов и 0 WAV,
и `play.sh` спотыкается на предпроверке списка с `Нет файлов …` и `exit 1`.

Проверка без риска для рабочих артефактов:

```bash
TTS_INPUT=/tmp/nope.txt ~/.pyenv/versions/silero/bin/python txtproc.py; echo $?   # 1, без трейсбека
printf '\xff\xfe' > /tmp/bad.txt
TTS_INPUT=/tmp/bad.txt ~/.pyenv/versions/silero/bin/python txtproc.py; echo $?    # 1, сообщение про кодировку
SILERO_INPUT=/tmp/nope.txt SILERO_OUTPUT_DIR=/tmp/x ~/.pyenv/versions/silero/bin/python silero10.py; echo $?  # 1, /tmp/x не создан
```

## `txtproc.py` — нормализация для Silero

Назначение: превратить произвольный русский текст в произносимую строку. Silero v5 плохо читает сырые цифры, даты, URL и латиницу, поэтому всё это раскрывается в слова **до** синтеза.

Скрипт не вызывает модель. Только текст.

### Точки входа

| Имя | Что делает |
|---|---|
| `normalize_text(text: str) -> str` | ядро. Для тестов и импорта. |
| `preprocess_text(file_path: str) -> str` | читает файл через `textio.read_text_file`, вызывает `normalize_text`. Ошибки входа — `InputError`. |
| `__main__` | `input.txt` → `silero_input.txt`. Ошибки входа — сообщение в stderr и `exit 1`; пустой вход — предупреждение `Пустой вход …` и `exit 0`. |

Импорт:

```python
from txtproc import normalize_text
print(normalize_text("в 2023 году было 90%"))
# в две тысячи двадцать третьем году было девяносто процентов
```

### Порядок шагов `normalize_text`

Порядок важен: узкие шаблоны раньше, «все оставшиеся `\d+`» в конце. Повторный прогон идемпотентен: `normalize_text(normalize_text(s)) == normalize_text(s)`.

1. **URL** — `http://`, `https://`, `www.` вырезаются вместе с необязательными скобками. Хеши в пути не читаются.
2. **Email** — вырезается.
3. **IPv4** — четыре октета `0–255` заменяются на `айпи-адрес`. Делается до дат, чтобы `10.1.80.31` не стал датой. `256.1.1.1` адресом не считается. Не трогает номер после `версия` / `версии` / `сборка` / `сборки` / `релиз` / `релиза` / `release` / `version` / `ver` / `ver.` / одиночной `v`: `версия 3.1.2.3` → `версия три точка один точка два точка три`, `v1.2.3.4` → `ви один точка …`. Голая четвёрка без такого слова остаётся адресом: `1.2.3.4` → `айпи-адрес`.
4. **Даты**
   - `ДД.ММ.ГГГГ`, `ДД/ММ/ГГГГ`, `ДД-ММ-ГГГГ` (оба разделителя одинаковые).
   - ISO `ГГГГ-ММ-ДД`.
   - Формат для русской речи: день.месяц.год, не американский MDY.
   - День существует в этом месяце (`calendar.monthrange`), включая 29 февраля високосного года. `31.02.2020` не дата: `тридцать один точка ноль два точка две тысячи двадцать`.
   - День: порядковое средний род (`двадцать седьмое`). Месяц: родительный. Год: порядковое родительный + `года`.
   - Пример: `27/11/2023` → `двадцать седьмое ноября две тысячи двадцать третьего года`.
5. **Время**. Час `0–23`, минуты и секунды — две цифры `00–59`. `ЧЧ:ММ:СС` всегда время. `ЧЧ:ММ` только после `в` / `к` / `ко` / `около` / `ровно` / `с` / `до`: `в 16:30`, `с 9:00 до 18:00`. По `с`/`до` час остаётся в именительном: `с 9:00` → `с девять часов ноль минут`, не `с девяти часов`. Точка в том же смысле, но без `с`/`до`: `в 12.30` → `в двенадцать часов тридцать минут`. Голое `3.14` остаётся дробью. `счёт 16:30` и `пропорция 4:20` не часы: после перевода чисел двоеточие между словами становится ` к ` (`шестнадцать к тридцать`). `16:9` тоже не время (минута из одной цифры): `в 9:5` → `в девять к пять`. Час `24` не время: `в 24:00` → `в двадцать четыре к ноль`. После `ЧЧ:ММ` не должно стоять `x` / `х` / `×` или ещё одно двоеточие: `в 16:30 x` читается числами и `к`, не часами.
6. **Телефон** с плюсом, 10–15 цифр. `+7` и ровно 10 цифр номера (всего 11) читаются группами: `+7 900 123-45-67` → `плюс семь, девять ноль ноль, один два три, четыре пять, шесть семь`. Иной код страны (`+3…`) и номер на `7` не из 11 цифр — первая цифра, дальше группы по три. Без плюса телефон не распознаётся.
7. **Годы** (`replace_years`, `year_inflection`)
   - `2026 г.г.` сначала сводится к `2026 г.`. Прочие `г.г.` становятся `гг.`.
   - `с 1999 по 2001` / `с 1999 года по 2001 год`: первое число родительный, второе винительный (`по две тысячи первый`), не дательный от одиночного `по`.
   - Диапазон без хвоста и без предлога `2014-2022` — два порядковых в родительном, между ними ` — `.
   - Диапазон с предлогом и без существительного берёт падеж предлога, оба конца в единственном: `в 2020-2021` → `в две тысячи двадцатом — две тысячи двадцать первом`.
   - Диапазон с существительным согласует оба конца в единственном числе с этим словом: `в 2020-2021 годах` → `в две тысячи двадцатом — две тысячи двадцать первом годах`.
   - `между 1990 и 2000` → оба года в творительном.
   - Предлог только с границей слова. `то 2020` не предложный: `то две тысячи двадцатый`.
   - Предлоги: `в/во/о/об/обо/при` предложный, `к/ко/по` дательный, `с/со/до/после/из/от/для/около/без/кроме/вне/внутри/вокруг/в течение/насчёт` родительный, `за/на/про/через/под` винительный, `над/перед/между` творительный. `насчет` без ё тоже родительный.
   - Если рядом однозначное слово (`год`, `года`, `годы`, `годом`, `годах`, …), падеж берётся у него, не у предлога. `на 2023 год` → `на две тысячи двадцать третий год` (`animate=False`). `в 1990-е годы` → `в … девяностые годы`.
   - `году` неоднозначно: падеж у предлога. `в 2023 году` → `… третьем году`, `к 2026 году` → `… шестому году`.
   - Десятилетия без `гг.`: `1990-е` → именительный множественный `… девяностые`; `1990-х` → родительный множественный `… девяностых`. `к 1990-м годам` → дательный множественный из-за слова `годам`. Голое `к 1990-м` — дательный единственный `… девяностому`: окончание `-м` само по себе единственное, предлог `к` ставит дательный.
   - `1990-е гг.` → именительный множественный `… девяностые годы`. `1990-х гг.` без предлога → `… девяностых годов`; после `в/во/о/об/обо/при/на` → `… девяностых годах`. Короткое `в 70-е гг.` так же: `в семидесятые годы` (точка после `гг.` уходит вместе с раскрытием, конечная точка предложения при этом сохраняется). Голое `гг. выпуска` и `гг. 1990` — слово `годы`, не слепое `годов`.
   - Суффикс `г.` и отдельное `г` (`2020 г`) раскрываются в `год/года/году/…` по падежу. Точка сохраняется, если дальше конец строки или пробел и заглавная: `в 2026 г. Потом` → `… года. Потом`. `в 2020 г. и дальше` точку не получает: следующее слово строчное.
   - Короткие числа перед «год»: `5 год` → `пятый год`, `к 5 году` → `к пятому году`. Голое `5 г` — это граммы, не год.
   - Одиночный `19xx`/`20xx` без контекста — порядковое именительный.
8. **Тире между числами** (после годов): `5–7` и `20%–30%` → пробелы и ` — `, чтобы слова не слипались. Единица после пары садится только на второе число: `5-7 км` → `пять — семь километров`. `±5` → `плюс-минус пять`. Одиночный минус `-5` → `минус пять`. `№ 5` → `номер пять`.
9. **Простые дроби** `a/b` из одной-двух цифр: `1/2` → `половина`, `2/3` → `две трети`, `1/3` → `одна треть`, `1/4` → `одна четверть`, `3/4` → `три четверти`. Остальные — числительное женского рода и порядковое знаменателя. Числитель на 1, кроме 11, даёт знаменатель в единственном (`1/5` → `одна пятая`), иначе родительный множественный (`2/5` → `две пятых`).
10. **Юбилеи** `30-летию` → `тридцатилетию` (родительный основа + тот же хвост). `100` → `сто`, `1000` → `тысяче`. Составные вроде `21-летие` склеиваются грубо.
11. **Латинская буква и число**: `F-16` → `эф шестнадцать`, `v1.2.3.4` → буква по имени (`ви`), не фонетическое `в`.
12. **Маркеры списка** в начале строки: `1.` / `2)` → `Первый.` / `Второй.`. Переводы строк к этому шагу ещё живы.
13. **Порядковые через дефис**, в том числе с тысячным пробелом: `1-й`, `2-го`, `в 1 000-м году` → `в тысячном году`. `90-е` при числе ≥ 20 и кратном 10 → множественное (`девяностые`), `2-е` → `второе`.
14. **Инициалы** до сокращений. Две или три буквы с точками, хотя бы одна заглавная: `А.С. Пушкин` → `а эс Пушкин`, `Т.Д. Иванов` и `Т. Д. Иванов` → `тэ дэ Иванов`, `т.Н. Иванов` → `тэ эн Иванов`, `Ф.И.О. заполни` → `эф и о заполни`. Все строчные (`т.д.`) не инициалы. Одна буква (`А. Пушкин`) не трогается. Четыре буквы с точками не шаблон: `А.Б.В.Г. Петров` → `А точка бэ вэ гэ Петров`.
15. **Сокращения с точкой**, только строчные:
    - `т.д.` → `так далее`, `т.е.` → `то есть`, `т.п.` → `тому подобное`, `т.к.` → `так как`, `т.н.` → `так называемый`, `и др.` → `и другие`, `и пр.` → `и прочее`, `н.э.` → `нашей эры`, `до н.э.` → `до нашей эры`. Точка возвращается на границе предложения (`т.д. Она` → `так далее. Она`, голое `т.д.` в конце → `так далее.`);
    - `ул.` → `улица`, `д.` перед числом → `дом` (`д.5` → `дом пять`), `рис.` → `рисунок`, `проф.` → `профессор`, `пр.` перед заглавной кириллицей → `проспект`, `стр.` → `страница`, `т.` перед числом → `том`;
    - `см.` → `смотри`, если перед ним нет числа. После числа это сантиметры, и точка остаётся: `5 см. текста` → `пять сантиметров. текста` (синтез режет фразу по этой точке);
    - `г.` перед заглавной **кириллицей** → `город` (`г. Москва`). Перед латиницей не город: `он сказал г. Paris` → `он сказал г. парис`.
    - Добавлены в T9.3: `тел.` → `телефон`, `корп.` перед числом → `корпус`, `коэф.` → `коэффициент`, `бульв.` → `бульвар`, `обл.` и `респ.` перед заглавной кириллицей → `область` / `республика`. Точка на границе предложения не ставится: после сокращения идёт имя, а не новая фраза. Главное — `silero10` больше не режет фразу посередине: `ул. Ленина, корп. 2. Он повернул налево.` даёт один фрагмент «улица Ленина, корпус два. Он повернул налево.», а не обрезок «улица.».
    Условие с заглавной буквой у `обл.`/`респ.` стоит не случайно: в конце предложения эти сокращения не разбираются (`Сокращение обл.` остаётся как есть), иначе на выходе появлялось `область.` посреди фразы. Именительный после предлога остаётся известным ограничением: `Он позвонил по тел.` → `по телефон` (так же ведёт себя существующее `ул.`).
    - Неизвестное `кв.5` теряет точку до перевода числа: `кв пять`, не `кв точка пять`.
16. **Единицы**, уже вместе с группировкой тысяч: `100 000 руб.` → `сто тысяч рублей`, `1 000 000 руб.` → `один миллион рублей`, `$1 000` → `одна тысяча долларов`, `1 500 кг` → `одна тысяча пятьсот килограммов` (не «полторы»). Дробь: `2.5 км` → `две целых пять десятых километра`; при дробной части единица в родительном единственного (`за 1,5 ч` → `… десятых часа`). Таблица: `% $ € ₽ руб кг шт км см мм мг м г ч мин сек ° сот. т.` плюс `млн`/`млрд` (`5 млн руб.` → `пять миллионов рублей`). `2,5 млн` домножается на миллион: `два миллиона пятьсот тысяч`; после запятой берётся не больше шести знаков. `т.` после числа — тонна. `$100` и `100$` оба работают. `€` читается `евро` во всех падежах, `₽` — как `руб`.
    Единицы вне прежней таблицы (T9.2): `га`, `л`, `Вт`, `В`, `т` без точки и `км/ч`. `5 га` → `пять гектаров`, `12 В` → `двенадцать вольт`, `5 Вт` → `пять ватт`, `2 л` → `два литра`, `0,5 т` → `ноль целых пять десятых тонны`, `40 км/ч` → `сорок километров в час`. Порядок альтернатив в `UNIT_RE` значим: `°C` стоит раньше `°`, иначе `°C` озвучивалось как `°к`; `км/ч` разбирается отдельным шаблоном `KMPH_RE` до `UNIT_RE`, потому что косая черта в таблицу не входит. `КПП`/`Вт` в верхнем регистре работают, новых коллизий с `кг`, `км`, `мг` нет (проверено регрессом).
    Знак валюты работает и рядом с `млн`/`млрд` — до числа, после масштабного слова или вместе с `руб.`: `$5 млн` и `5 млн $` → `пять миллионов долларов`, `€3 млн` → `три миллиона евро`, `₽7 млн` → `семь миллионов рублей`, `1,2 млрд $` → `один миллиард двести миллионов долларов`, `$5 млн руб.` → `пять миллионов рублей`. Одиночный знак без числа (`у него $ и €`) вычищается в cleanup вместе с лишним пробелом; знак при числе (`300$`) по-прежнему читается словом. Чужой знак не перехватывается: в `5 млн $100` доллар относится к 100, а не к миллионам.
16a. **Градусы и надстрочные единицы** (T9.1) сразу после единиц. `20 °C` → `двадцать градусов Цельсия`, `-5 °C` и `−5°C` → `минус пять градусов Цельсия`, голое `20°` остаётся `двадцать градусов`. Надстрочные: `5 км²` → `пять квадратных километров`, `1 км²` → `один квадратный километр`, `23 км²` → `двадцать три квадратных километра`, `5 см²` → `пять квадратных сантиметров`, `0,5 м³` → `ноль целых пять десятых кубического метра`. Знак без числа (`км²`) не трогается.
    Градус после словесного числа (`упала до минус пяти °C`) разбирается отдельным списком `DEGREE_C_GENITIVE_WORDS`, потому что цифра к этому шагу уже стала словом. Список покрывает формы родительного/предложного падежа (`пяти`, `двадцати`, `сорока`, `десяти`); составные и именительные формы сознательно не обрабатываются: `минус пять °C` остаётся с `°к`. Ограничение зафиксировано кейсом в `tests/cases.txt` и проверкой в `tests/test_normalize.py`.
16b. **Номерные идентификаторы** (T9.4) сразу после телефонов: после слов `ИНН`, `КПП`, `СНИЛС`, `ОГРН` число читается по одной цифре — `ИНН 7707083893` → `ИНН семь семь ноль семь ноль восемь три восемь девять три`, `СНИЛС 112-233-455 95` → цифры по одной. Без ключевого слова число остаётся количеством: `у него 7707083893 рублей` читается как миллиарды. Эвристика «список чисел vs одно число» (T9.4, опционально) не делалась.
17. **Тысячи с пробелом/nbsp** без единицы: `100 000` → `сто тысяч`, `1 000,5` → `одна тысяча целых пять десятых`, `1 000 000,5` → `один миллион целых пять десятых`. Группировка ограничена тремя кластерами после первой, то есть 12 цифрами (`999 999 999 999` читается как одно число, `1 000 000 000 000 000` — нет); дробная часть — не длиннее 12 знаков. Целое длиннее 12 цифр читается по одной цифре, поэтому `normalize_text` не падает ни на каком входе: ряд `100 100 100 …` из двадцати членов и thousands-цепочка из 1440 членов дают текст, а не `KeyError`/`ValueError` из `num2words`.
18. **Перечисления** из трёх и более целых через запятую не дробь: `5,6,7` → `пять, шесть, семь`. Пробел после запятой сохраняется. `5,6` по-прежнему одна дробь.
19. **Десятичные** с одной запятой или точкой, по записанным цифрам: `3.14` → `три целых четырнадцать сотых`, `3.10` → `три целых десять сотых`. Несколько точек (`1.2.3`) не дробь. Миллион и больше: целая часть отдельно, чтобы не вышло «одна миллион». Дробь длиннее 12 знаков не отдаётся в `num2words` (там float и `5E-21`): цифры читаются по одной, `0,000…005` не роняет процесс.
20. **Разрезание** `VPN01` → `VPN 01`, затем число отдельно.
21. **Оставшиеся целые** — количественные. Длиннее 12 цифр — по одной цифре.
22. **Римские числа** только рядом со словом `век` / `столетие` / `глава` / `статья` / `часть` / `том`: `XX век` → `двадцатый век`, `в XX веке` → `в двадцатом веке`, `глава II` → `глава вторая`. Голое `XX` без такого слова уходит в латиницу.
23. **Латиница**:
    - словарь `ACRONYMS` без учёта регистра (`Vpn` → `ви-пи-эн`): `VPN` `ви-пи-эн`, `ISW` `ай-эс-дабл-ю`, `HTTP` `эйч-ти-ти-пи`, `HTTPS` `эйч-ти-ти-пи-эс`, `USA` `ю-эс-эй`, `USB` `ю-эс-би`, `SSD` `эс-эс-ди`, `HDD` `эйч-ди-ди`, `CPU` `цп-у`, `GPU` `гп-у`, `IP` `айпи`, `TV` `ти-ви`, `AI` `ай`, `IT` `ай-ти`, `OK` `окей`, `RAS` `рас`, `WWW` `ввв`;
    - прочие ALLCAPS из 2–4 букв — имена букв через дефис (`NATO` → `эн-эй-ти-оу`), не фонетическая склейка `н-а-т-о`. Слово из 5 букв и длиннее идёт фонетикой (`ABCDE` → `абкде`);
    - остальные слова — фонетическая транслитерация. Диграфы: `sch→щ`, `sh→ш`, `ch→ч`, `zh→ж`, `yo→ё`, `yu→ю`, `ya→я`, `ye→е`, `ph→ф`, `th→т`, `kh→х`. `c` перед `e/i/y` → `с`, иначе `к`;
    - `\` → пробел (`campus\ekochetova`).
24. **cleanup** не схлопывает переводы строк (абзац остаётся границей для `silero10`). Точка между буквами (`один.два`) → ` точка `. Двоеточие между словами → ` к `. Пустые `()` `[]` выкидываются. Пробел перед `,.;:!?` снимается. Лишние пробелы схлопываются, пробелы у краёв скобок тоже. Одиночный `$`/`€`/`₽` без числа рядом (ни перед ним, ни после) удаляется: `у него $ и €` → `у него и`.

### Ключевые хелперы

- `ru_num(n, to=..., case=..., gender=..., plural=...)` — обёртка над `num2words`, `lang='ru'`.
- `ru_plural(n, one, few, many)` — русское согласование числительного.
- `date_to_words` / `time_to_words` / `year_to_words` / `number_and_unit`.

Падежи `num2words` (русский): `n` именительный, `g` родительный, `d` дательный, `a` винительный, `i` творительный, `p` предложный. Род: `m` `f` `n`.

### Чего препроцессор не делает

- Полное согласование любого числа с предлогом (`до девяносто процентов` остаётся; `с 9:00` → `с девять часов ноль минут`, не `с девяти`).
- Телефон без плюса. ИНН и счета длиннее 12 цифр по-прежнему по одной цифре.
- «Полторы тысячи» для 1500: число читает `num2words`, получается `одна тысяча пятьсот`.
- Римские числа без соседнего `век/глава/статья/часть/том/столетие`.
- Американские даты MDY. Все `05/03/2026` — 5 марта.
- Сокращения вне списка (`кв.`, `др.` без «и»). Одна инициальная буква (`А. Пушкин`) не раскрывается. Четыре инициала подряд не съедаются целиком. `г.` без следующей заглавной кириллицы не становится «город».
- Аккуратную основу составного юбилея (`21-летие`).
- SSML. Препроцессор отдаёт чистый текст; обёртку `<speak><prosody rate=…>` собирает `silero10.py`.
- Морфологию через pymorphy. Согласование единиц — таблица 1/2–4/5+, у дроби родительный единственного.
- Различить «несколько чисел через пробел» и «одно число с разделителями». После `1 000 000 000` группа перестаёт склеиваться, но ряды вида `100 200 300 400 500` короче 12 цифр всё ещё читаются одним числом — `сто миллиардов двести миллионов триста тысяч четыреста пятьсот`. Аналогично `1 000 2 000 3 000` — это уже три отдельных числа.

### Зависимости `txtproc.py`

Только stdlib `re`, `sys` и `num2words` (в env стоит 0.5.14), плюс локальный `textio.py` для
чтения входа. `pymorphy3` / `razdel` / `natasha` не нужны.

## `silero10.py` — синтез

Актуальный TTS-скрипт. Читает уже нормализованный текст и пишет по одному WAV на предложение. Темп речи — аргумент CLI, не константа.

### Константы (менять здесь)

| Имя | Сейчас | Смысл |
|---|---|---|
| `voice` | `"aidar"` | голос внутри модели. Допустимы `aidar`, `baya`, `kseniya`, `xenia`, `eugene` |
| `input_file` | `"silero_input.txt"` | выход `txtproc.py` |
| `output_dir` | `"silero_output"` | папка WAV |
| `language` | `"ru"` | язык для `torch.hub.load` |
| `sample_rate` | `48000` | 8000 / 24000 / 48000 |
| `device` | авто: `cuda`, если `torch.cuda.is_available()`, иначе `cpu`. `SILERO_DEVICE` перебивает | GPU. На этой машине GTX 1080 + torch `2.1.2+cu118` работает |
| `speaker=` в `hub.load` | `"v5_6_ru"` | **id модели**, не голос |
| `RATES` | `{1: "x-slow", … 5: "x-fast"}` | карта CLI → SSML `prosody rate` |
| `HEADROOM_DB` | `-1` (`SILERO_HEADROOM_DB`) | запас по громкости в dBFS, к которому подтягивается пик фрагмента; `0` — выключено |
| `CLIPPING_LEVEL` | `0.999` | порог «это уже клиппинг» в тестах (D12) |
| `MAX_CHUNK_CHARS` / `MIN_GLUE_CHARS` | `500` / `25` | потолок длины фрагмента и порог склейки. Объявлены в `chunking.py`, `silero10.py` их импортирует |

Путаница, из-за которой уже ломалась генерация: аргумент `speaker` в `torch.hub.load` — имя пакета модели (`v5_6_ru`), а голос передаётся в `model.apply_tts(..., speaker=voice)`.

### CLI скорости

`silero10.py` без аргумента и `silero10.py 3` — `medium`. `silero10.py 4` — `fast`. Не число или вне `1`–`5` — сообщение на stderr и `sys.exit(1)`, до чтения текста и загрузки модели. Запускать тем же интерпретатором, что и `play.sh`: `~/.pyenv/versions/silero/bin/python`.

Разбор: `parse_rate(sys.argv)` → `(rate_n, speech_rate)`. Имя тега (`slow`, `fast`, …) живёт только здесь; `play.sh` пробрасывает цифру.

### Хелперы

| Имя | Что делает |
|---|---|
| `parse_rate(argv)` | argv → `(int, str)`. Нет аргумента → `(3, "medium")`. Лишний аргумент — `exit 1`. |
| `to_ssml(sentence, rate)` | `<speak><prosody rate="…">…</prosody></speak>`. Текст через `xml.sax.saxutils.escape` (`&`, `<`, `>`). |
| `split_into_sentences` | `.!?` и перевод строки. Внутри корректно закрытой кавычки `«»`, `"`, `“”` и `„“` не режет; незакрытая опечатка режим не включает (T7). Многоточие `…` границу не ставит. Закрывающие `»”)]` после знака остаются в том же фрагменте ровно один раз. Цепочка `??!` — одна граница. Живёт в `chunking.py`. |
| `glue_short_sentences` | кусок короче 25 символов клеится к соседу, если оба кончаются на `.!?` или `…` и склейка не длиннее 500. Заголовок без этих знаков не клеется. В `chunking.py`. |
| `split_long_chunks` | кусок длиннее `MAX_CHUNK_CHARS` (500) дорезается. Ищется правый `;`, потом `:`, потом `,`, потом пробел в окне от трети лимита до лимита. `;` и `:` остаются в левом куске, запятая и пробел — нет. Нет разреза — рез по символу 500. В `chunking.py`. |
| `prepare_chunks` | split → склейка → дорезка. Это то, что идёт в модель. В `chunking.py`. |
| `render_sentences` | пишет `out_NNNN.wav`, возвращает `(успехи, ошибки, секунды)`. С `SILERO_RESUME=1` пропускает индекс, если `out_NNNN.wav` уже есть в выходном каталоге. |
| `normalize_peak(audio, headroom_db=HEADROOM_DB)` | подтягивает пик волны к `HEADROOM_DB` одним коэффициентом по всему фрагменту (T12/D12). Тип волны сохраняет (`torch.Tensor` остаётся тензором), тишину не трогает. |
| `save_atomic(writer, filepath, audio, sample_rate)` | пишет WAV во временный файл `.out_*` рядом и подменяет цель через `os.replace`. Нужно для `--resume`: жёсткая ссылка на рабочий WAV не перезаписывается частичной волной. |
| `is_resume_enabled()` | `SILERO_RESUME == "1"` — единственное место, где читается флаг. |
| `read_text_file` (из `textio.py`) | читает `input_file` как `utf-8-sig`; нет файла / не UTF-8 / нет прав → `InputError`. Общий с `txtproc.py` текст сообщений. |

### Алгоритм

1. `parse_rate` — ещё до чтения файла. Весь запуск под `if __name__ == "__main__"`: импорт модуля модель не грузит.
2. Читает `silero_input.txt` через `textio.read_text_file` и `strip()`. Нет файла или не UTF-8 — сообщение в stderr и возврат `1`, ещё до `os.makedirs` и до загрузки модели: каталог выхода при такой ошибке не создаётся, а staging `play.sh` остаётся пустым.
3. `os.makedirs(output_dir, exist_ok=True)` — только для успешного чтения входа.
4. `prepare_chunks` (из `chunking.py`): перевод строки — граница абзаца; `.!?` режут только вне корректно закрытых кавычек `«»` `"“„`; незакрытая кавычка режим не включает; многоточие `…` фразу не рвёт; заголовок без точки остаётся отдельным фрагментом (`Что происходит на фронте` не склеивается со следующей фразой); подряд идущие короткие фразы с точкой склеиваются (`Славянск.` `Краматорск.` `Дружковка.` `Константиновка.` → один фрагмент); всё длиннее 500 символов дорезается по `;:`, запятой и пробелу, а слово без пробелов — посимвольно по 500. Модель v5_6_ru падает примерно после 1000 символов (`Model couldn't generate your text, probably it's too long`); 500 — запас. Пустой текст даёт 0 фрагментов и `exit 0` ещё до загрузки модели; `play.sh` затем не находит wav и выходит с `1`.
4a. `--resume` (`SILERO_RESUME=1`, в `play.sh` — флаг `--resume`): `render_sentences` пропускает индекс, если `out_NNNN.wav` с этим номером уже есть в выходном каталоге. Работает вместе со staging: `play.sh` перекидывает готовые файлы рабочего каталога в staging **жёсткими ссылками** и выставляет `SILERO_RESUME=1`, поэтому недостающие фразы дописываются в тот же каталог, а подмена после успеха не трогает пропущенные (у них тот же inode). В конце прогона печатается `Пропущено готовых фрагментов: N` и строка `Режим --resume: …`. Без флага поведение прежнее — синтезируются все фрагменты, окружение не выставляется.
5. Грузит модель. Обёртка hub `TTSModelMultiAcc_v3` не `nn.Module` и метода `eval()` не имеет. Генерация идёт внутри `torch.no_grad()`:

```python
model, _ = torch.hub.load(
    repo_or_dir="snakers4/silero-models",
    model="silero_tts",
    language="ru",
    speaker="v5_6_ru",
    trust_repo=True,
    verbose=False,
)
model.to(device)
```

6. Для каждого предложения вызывает

```python
audio = model.apply_tts(
    ssml_text=to_ssml(sentence, speech_rate),
    speaker=voice,          # aidar
    sample_rate=48000,
    put_accent=True,
    put_yo=True,
)
save_atomic(sf.write, f"{output_dir}/out_{idx:04d}.wav", normalize_peak(audio), sample_rate)
```

Обычный `text=` больше не передаётся. `medium` тоже идёт через SSML, один код-путь на все пять скоростей.

6a. `normalize_peak` вызывается перед записью, а не после (T12). Модель пишет волновую форму впритык
к 0 dBFS, а `sf.write` без `subtype` — это PCM_16: там `1.0` превращается в клиппующий сэмпл
(в выборке 26 файлов аудита такие сэмплы нашлись в трёх, D12). Правка — одно умножение на
`limit / peak`, где `limit = 10**(HEADROOM_DB/20)`; усреднения, компрессии и шумоподавления нет,
поэтому тембр и длительность не меняются, а темп речи по-прежнему задаёт только SSML. Работает
в обе стороны: тихий фрагмент усиливается до той же цели. Отключение — `SILERO_HEADROOM_DB=0`
(тогда в конце прогона печатается `Headroom выключен (SILERO_HEADROOM_DB=0)`); положительное
значение тоже выключает правку, потому что выше 0 dBFS физически ничего не помещается.
Замер на GPU: волна с пиком `1.0` после правки даёт `0.8913` — это ровно −1 dBFS; при
`SILERO_HEADROOM_DB=0` те же две фразы остаются с пиками `0.98` и `0.92`. Схема выхода не
менялась: по-прежнему PCM_16, 48 кГц, mono.

6b. `save_atomic` — временный файл `.out_XXXX.wav` в том же каталоге и `os.replace` на финальное
имя. Нужно это ради `--resume`: в staging файлы прилетают жёсткими ссылками на рабочий каталог,
и прямая запись писала бы поверх прежнего результата (а при падении посередине оставляла бы битый
файл и там, и там). Имя временного файла начинается с точки — в шаблон `out_NNNN.wav` оно не попадает,
поэтому полузаписанный фрагмент не попадёт ни в `list.txt`, ни в счётчик пропусков `--resume`.

7. Ошибка на одном фрагменте печатается в stderr (`ОШИБКА на предложении N`) и цикл идёт дальше. Файл этого индекса не создаётся. В конце строка `Готово: N файлов, M ошибок, суммарно X.X с`. Если ошибок больше нуля, `main` возвращает `2`. `play.sh` из-за `set -e` не запускает `ffplay` на дырявой склейке.

`chunking.py` — нарезка (импорт оттуда же). `textio.py` — чтение входа и текст сообщений об ошибках входа. `sys` — скорость и код возврата. `numpy` — пик волны в `normalize_peak`. `tempfile` — временный файл в `save_atomic`. `xml.sax.saxutils.escape` — `to_ssml`. Импорта `datetime` и `re` нет.

Флаги `put_stress_homo` и `put_yo_homo` в вызов `apply_tts` не передаются. У модели v5 дефолт обоих — `True`, омографы и «ё» включены. Чтобы выключить, передать `False` в `apply_tts`, не в `hub.load`. В `silero9.py` они передаются явно.

### Модель Silero

Актуальная русская линейка (GitHub `models.yml`):

| id | заметка |
|---|---|
| `v5_6_ru` | стоит в `silero10.py`, веса `v5_6_ru.pt` |
| `v5_5_ru` | вопросы да, акцент/восклицания нет |
| `v5_4_ru` | без `eugene` |
| `v5_3_ru` … `v5_ru` | старше |

Веса **не** входят в pip-пакет `silero==0.5.5`. Пакет — только загрузчик. `silero10.py` идёт через `torch.hub`, кэш:

```
~/.cache/torch/hub/snakers4_silero-models_master/
    models.yml                          # список id моделей
    src/silero/model/v5_6_ru.pt         # веса
```

Если в `models.yml` нет нужного id, будет:

```
AssertionError: Speaker not in the supported list [...]
```

Это кэш репозитория, не pip. Обновление:

```python
torch.hub.load(..., speaker="v5_6_ru", trust_repo=True, force_reload=True)
```

или удалить `~/.cache/torch/hub/snakers4_silero-models_master` и запустить снова. `force_reload=True` нужен один раз, в постоянном коде его держать не стоит.

pip `silero 0.5.5` внутри `__version__` всё ещё пишет `0.1.0` — ориентироваться на `pip show silero`.

### Установка с нуля

Проверяется без GPU и без скачивания колёс: `pip install --dry-run` разрешает весь
`requirements.txt` вместе с флагом индекса (rc 0) и отказывается без него (rc 1,
`Could not find a version that satisfies the requirement torch==2.1.2+cu118`). Полная установка
в свежем venv на этой машине не проверялась только потому, что это ещё ~2 ГБ колёс рядом с
рабочим env.

```bash
# 1. системные зависимости (Debian/Ubuntu)
sudo apt-get install ffmpeg libsndfile1
#    ffmpeg      — нужен ffplay, только для воспроизведения; для синтеза не обязателен
#    libsndfile1 — грузит soundfile (запись WAV): без него падает silero10.py

# 2. окружение. Именно python 3.10: под 3.11+ wheel torch-2.1.2+cu118 не выпущен.
python3.10 -m venv ~/.pyenv/versions/silero
~/.pyenv/versions/silero/bin/python -m pip install --upgrade pip

# 3. пакеты. --extra-index-url обязателен: тегом +cu118 собраны torch и torchaudio,
#    на PyPI их нет (без флага разрешение падает на «Could not find a version that
#    satisfies the requirement torch==2.1.2+cu118»). Тот же текст — в шапке requirements.txt.
~/.pyenv/versions/silero/bin/python -m pip install \
    --extra-index-url https://download.pytorch.org/whl/cu118 -r requirements.txt
```

Проверки после установки (все проходят на этом env):

```bash
PY=~/.pyenv/versions/silero/bin/python
$PY -m pip check                     # No broken requirements found
$PY -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
                                     # 2.1.2+cu118 11.8 True
ls ~/.pyenv/versions/silero/lib/python3.10/site-packages/nvidia/cudnn/lib/libcudnn.so.8
~/.pyenv/versions/silero/bin/python tests/test_normalize.py    # OK <N> cases, …
```

`torch.cuda.is_available()` без `LD_LIBRARY_PATH` не требует: проверка библиотек cuDNN
случается при первом CUDA-операторе. Полный прогон `./play.sh` сам добавляет путь к
`libcudnn.so.8` в первой строке — но та же строка вызывает голый `python`, поэтому интерпретатор
должен быть в `PATH` (или в `LD_LIBRARY_PATH` уже лежит путь к cuDNN). Это известная шероховатость
оболочки, а не требование установки.

Версию `libsndfile1` видно из Python: `python -c "import soundfile; print(soundfile.__libsndfile_version__)"`
(на этом env 1.2.2).

Ставить нужно в env `silero`, а не в system python: `requirements.txt` — снимок именно его, и
`play.sh` берёт интерпретатор оттуда.

### torch.hub, `trust_repo` и офлайн-запуск

`silero10.py` грузит модель так:

```python
torch.hub.load("snakers4/silero-models", model="silero_tts", language="ru",
               speaker="v5_6_ru", trust_repo=True, verbose=False)
```

`trust_repo=True` — это не «доверять весам», а «клонировать и **исполнить** код удалённого
репозитория без подтверждения». torch клонирует `master` (не тег) и импортирует его `hubconf.py`.
Значит: нужна сеть при пустом кэше, а содержимое кэша — исполняемый код третьей стороны.
Менять это решение задачи не стоят; если нужен воспроизводимый запуск — держать непустой
кэш и не чистить его (офлайн-режим ниже).

Кэш: `~/.cache/torch/hub/snakers4_silero-models_master/` (`models.yml`,
`src/silero/model/v5_6_ru.pt` ~141 МБ). Путь переопределяется `TORCH_HOME` (тогда кэш —
`$TORCH_HOME/hub`) или `TORCH_HUB`. Пустой клон занимает ~2 МБ, веса догружаются один раз.

Офлайн-запуск — когда в кэше уже есть `models.yml` и `v5_6_ru.pt`:

```bash
TORCH_HOME=/home/ant0m/.cache/torch ./play.sh 3   # сеть не трогает: кэш на месте, hub не клонирует
```

Работает без `HF_HUB_OFFLINE`: torch.hub сам пропускает клонирование, если каталог кэша уже
есть (флаг `HF_HUB_OFFLINE` относится к huggingface_hub, а не к torch.hub). Проверено: при
непустом `~/.cache/torch/hub/snakers4_silero-models_master/` прогон не обращается в сеть.

На этом env кэш заполнен (id `v5_1_ru`…`v5_6_ru`), поэтому прогон работает без сети.
При пустом кэше без сети падение выглядит как ошибка git-клонирования или
`URLError`, и по T2 рабочий каталог при этом остаётся целым. Если сеть есть, но репозиторий
не клонируется (прокси, самоподписанный сертификат) — тот же путь: склонировать вручную в
каталог кэша и запускать офлайн.

### CUDA 11 и CUDA 13 в одном env

В env `silero` соседствуют два поколения CUDA-библиотек, и это не поломка, а наследие одной
установки. Факты, полученные разбором этого env:

| Что | Значение |
|---|---|
| torch | `2.1.2+cu118` (CUDA 11.8), driver 580.196.07, GTX 1080 |
| откуда берутся библиотеки CUDA 11 | почти все **вшиты в wheel torch** с патченными sonames (`libcudart-d0da41ae.so.11.0`, `libcublas.so.11` в `torch/lib/`) — системный CUDA не нужен |
| единственная внешняя | `libcudnn.so.8` из колеса `nvidia-cudnn-cu11` — её и добавляет `LD_LIBRARY_PATH` в первой строке `play.sh` |
| `-cu11` пакетов в env | три: `nvidia-cudnn-cu11`, `nvidia-cublas-cu11`, `nvidia-cuda-nvrtc-cu11` (последние два — зависимости первого) |
| CUDA-13 набор | `cuda-bindings` → `cuda-toolkit[all]` → `nvidia-cublas 13.x`, `nvidia-cudnn-cu13 9.24`, `nvidia-nccl-cu13`, `nvidia-cusparselt-cu13`, `nvidia-nvshmem-cu13` и др. Пайплайн их **не использует** |
| пересечение каталогов | `nvidia-cudnn-cu11` и `nvidia-cudnn-cu13` пишут в один `site-packages/nvidia/cudnn/lib/`: `.so.8` и `.so.9` рядом, имена библиотек не пересекаются |
| реальный конфликт | три файла заголовков (`cudnn.h`, `cudnn_backend.h`, `cudnn_version.h`) перезаписаны версией 9; на пайплайн не влияет — он ничего не компилирует. Влияет на сборку CUDA-расширений в этом env |
| кто владеет `__init__.py` | пустые `nvidia/__init__.py`, `nvidia/cudnn/__init__.py` и `nvidia/cudnn/lib/__init__.py` записаны в RECORD **обоих** колес cudnn — отсюда и риск удаления |

**Решение (T5/D6): набор CUDA 13 оставить как есть и не удалять его выборочно.** Причины:

1. `import nvidia.cudnn`, из которого `play.sh` берёт путь к `libcudnn.so.8`, — обычный пакет
   (не namespace): пустые `__init__.py` в `nvidia/`, `nvidia/cudnn/` и `nvidia/cudnn/lib/`
   записаны в RECORD обоих колес cudnn, а не одного. `pip uninstall nvidia-cudnn-cu13`
   удаляет эти `__init__.py` вместе со своими `.so.9`: `import nvidia.cudnn` начинает бросать
   `ModuleNotFoundError`, а первая строка `play.sh` падает до всякого синтеза (проверено на
   копии env). Именно поэтому вариант «удалить CUDA 13 из env» требует правки `play.sh`,
   а не только `requirements.txt`.
2. `pip check` на текущем env чист: зависимости CUDA-13 колес закрыты, конфликтов нет.
3. Польза от удаления — ~1,3 ГБ свободного места, риск — рабочий GPU-прогон.

Что из этого следует на практике:

- **правку env делать целиком через `requirements.txt`** (`pip install -r …`), а не точечными
  `pip install/uninstall`: выборочное удаление пакетов cudnn ломает `import nvidia.cudnn`;
- `nvidia-cudnn-cu11` удалить нельзя — без `libcudnn.so.8` inference падает на
  `Could not load library libcudnn_ops_infer.so.8` (это и есть D5, снятый с плана);
- если CUDA-13 стек всё же захотят вынести: вместе с ним убирать весь блок `cuda-bindings` /
  `cuda-toolkit` / `nvidia-*` без суффикса `-cu11` (в нём 18 пакетов, они связаны зависимостями
  через `cuda-toolkit[all]`), после чего в `play.sh` заменить
  `import nvidia.cudnn` на поиск `libcudnn.so.8` через `importlib.metadata.files(...)` или
  жёсткий путь env `silero`, и перепроверять весь список CLI-сценариев;
- если в `LD_LIBRARY_PATH` попадёт каталог с `.so.9`, torch 2.1.2 всё равно возьмёт `.so.8`
  (soname зашит в `libtorch_cuda.so`), так что конфликт поколений сам по себе его не ломает;
- если вместо `apt-get install libsndfile1` кто-то поставит `pysoundfile`=колесо `soundfile`
  с встроенной библиотекой — не поможет: `libsndfile` ищется в системе, см. «Установка с нуля».

Быстрая диагностика окружения:

```bash
SP=~/.pyenv/versions/silero/lib/python3.10/site-packages
ls $SP/nvidia/cudnn/lib | grep -c '\.so\.8$'      # 7 — инференсные библиотеки cuDNN 8
python -c "import nvidia.cudnn; print(nvidia.cudnn.__path__[0])"   # путь для LD_LIBRARY_PATH
LD_LIBRARY_PATH=$SP/nvidia/cudnn/lib python -c "import torch; print(torch.cuda.is_available())"
# вариант без env silero: тот же soname лежит рядом с самим torch, в torch/lib/
python -c "import torch, os; print(os.path.join(os.path.dirname(torch.__file__), 'lib'))"
```

## Как дорабатывать

### Текст читается неправильно

Править `txtproc.py`, не модель.

- Новый тип (телефон, №, диапазон `5–7 км`) — добавить функцию **выше** `replace_remaining_numbers` и вставить вызов в `normalize_text`.
- Новая латинская аббревиатура — словарь `ACRONYMS`. Новое русское сокращение с точкой — список `ABBREVIATION_RES` (только строчные буквы). Имена букв инициалов — `CYR_LETTER_NAME`.
- Проверка без синтеза: `~/.pyenv/versions/silero/bin/python tests/test_normalize.py`. Одна фраза: `…/python -c "from txtproc import normalize_text; print(normalize_text('...'))"`.
- Ожидания лежат в `tests/cases.txt` (таб: фраза, результат), не в текущем `input.txt`. Туда же добавлять новый регресс. `normalize_text` идемпотентна, тест это проверяет. Нарезку (`prepare_chunks` из `chunking.py`, ошибки синтеза через заглушку) тест гоняет без модели; проверки нарезки T7 (незакрытая кавычка, дубли `??!` и `..`) лежат кодом в `tests/test_normalize.py`, а не строками в `cases.txt`: ожиданием тут служит структура списка фрагментов.
- Поведение входа (нет файла, не UTF-8, пустой вход) — тоже контракт, но в `cases.txt` оно не выражается
  (там только «фраза → ожидание»). Такие проверки лежат кодом в `tests/test_normalize.py`:
  часть — вызовом `textio.read_text_file`, часть — реальным запуском `txtproc.py`/`silero10.py`
  как скриптов с перенаправленными в `/tmp` путями. Менять текст сообщения можно только
  вместе с этими проверками: они сверяют подстроки (`Нет входного файла`, `не в UTF-8`, `UTF-16`,
  `Пустой вход`) и коды возврата.
- Громкость и запись WAV (T12, T14) — тоже код в `tests/test_normalize.py`, не строка в `cases.txt`:
  `check_headroom` синтезирует фрагмент заглушкой модели и читает уже **записанный** файл через
  `soundfile` (пик обязан быть ниже `CLIPPING_LEVEL` и равняться цели `HEADROOM_DB`), `check_resume_and_atomic`
  считает пропуски `--resume`, отсутствие временных `.out_*` и сохранность жёсткой ссылки. Менять
  `HEADROOM_DB` можно только вместе с ними: ожидание вычисляется из константы, а не зашито числом.

### Другой голос / модель / GPU

Быстрый путь — флаги `play.sh`: `./play.sh --voice baya --device cpu --no-play`. Они только ставят `SILERO_VOICE` / `SILERO_DEVICE`.

Постоянная смена — править константы в `silero10.py`. После смены id модели первый запуск скачает `.pt` (~140 МБ) в кэш hub.

### Скорость речи

Не трогать `ffplay` и `sample_rate`. Темп задаёт SSML в `silero10.py` (`ssml_text=`, тег `<prosody rate>`). Запас по громкости (`normalize_peak`) темп не меняет: это одно умножение на константу, без time-stretch и без `atempo`. Запуск: `./play.sh 2` или `~/.pyenv/versions/silero/bin/python silero10.py 2`. Карта `1`–`5` живёт в `RATES`; `play.sh` только проверяет диапазон и пробрасывает число. Новое имя тега — править `RATES`, оба CLI подхватят его.

### Другой вход/выход

Пути — переменные окружения с дефолтами, их выставляет `play.sh` и читают оба скрипта (`TTS_INPUT`, `SILERO_INPUT`, `SILERO_OUTPUT_DIR`, `SILERO_LIST`). Менять дефолт нужно в `play.sh` и в `os.environ.get(...)` скрипта, который запускают отдельно от оболочки.

Проверка готовности результата без проигрывания: `ffprobe -v error -show_entries stream=codec_name silero_output/out_0001.wav`. Ровно этот вызов (для первого и последнего файла списка) делает `probe_first_last` в `play.sh`; своя предпроверка обязана сохранять код возврата прогона — `ffplay` на битом WAV возвращает 0, и это уже учтено (D8).

### Как режется текст

`prepare_chunks` и всё, что от неё зависит, живут в `chunking.py`; `silero10.py`
импортирует их оттуда. Модуль написан без `torch`, чтобы тесты нарезки запускались
без GPU и без скачанной модели.

- перевод строки из `txtproc.cleanup` не схлопывается, заголовок без точки остаётся своим фрагментом;
- `.!?` режут фразу, но не внутри `«»`, `"`, `“”` и `„“`. Многоточие `…` границу не ставит. Закрывающие `»”)]` после знака остаются в том же фрагменте;
- **незакрытая кавычка больше не склеивает абзац** (T7). Кавычка включает режим «внутри реплики», только если является настоящей: закрывающий символ существует, стоит до конца абзаца и сразу за ним — конец текста или пробел. Опечатка в одной `«` («Он сказал «привет. Как дела. конец») режим не включает, и фраза режется по `.!?` как обычно, а не превращается в один кусок, который дорезается по запятой где попало. Перевод строки закрывает кавычку: соседний абзац не приклеивается и не теряет свою озвучку. Известное ограничение: если закрытие стоит после конца предложения (««Первая строка. Третья.» И конец.»), режим тоже не включается и цитата режется как обычный текст;
- цепочка `??!` — одна граница фразы, а не три; раньше по ней резалось по одному знаку, и на выходе появлялись обрывки вида `?` / `!`. Символы кавычек после `.!?` входят во фрагмент ровно один раз: прежний код добавлял их в буфер и затем перечитывал, из-за чего в озвучку попадали `помещение?»?`, `уехал..` и `Франции??!` (при исходном `?!`), а перенос строки внутри цитаты съедался и «быстро— и\nнизколетящего» склеивалось в «инизко». Все эти дубли правятся на реальном `silero_input.txt`: 649 фрагментов стало 657, максимальная длина куска 227 → 168 символов, входов длиннее 500 не осталось;
- точка у `г.` / `т.д.` в конце предложения сохраняется, две фразы не слипаются;
- короткие куски с `.!?` или `…` (порог 25 символов) склеиваются с соседом, если склейка не длиннее 500, поэтому `Краматорск. Дружковка.` не становятся отдельными WAV;
- фрагмент без `.!?…` (заголовок) ни к кому не клеится;
- длиннее 500 символов дорезается: правый `;` или `:`, иначе запятая, иначе пробел. `;` и `:` остаются в левом куске. Нет разреза — рез по символу 500, чтобы не упереться в лимит модели (~1000).

Порог склейки — `MIN_GLUE_CHARS`, потолок — `MAX_CHUNK_CHARS`. Оба объявлены в `chunking.py`, `silero10.py` импортирует их оттуда (старые импорты из `silero10` продолжают работать).

### Обновление Silero

1. `pip install -U silero` обновляет загрузчик, не веса и не `models.yml` в hub-кэше.
2. Обновить кэш hub (`force_reload` или удалить папку).
3. Прописать новый id в `silero10.py` (`speaker="v5_N_ru"`).
4. Проверить, что id есть в свежем `models.yml`. Несуществующий id валит скрипт до генерации.

## Известные грабли

1. История: `speaker="v5_5_ru"` при hub-кэше марта 2026 падал — в тогдашнем `models.yml` не было этого id. Сейчас в кэше есть `v5_1_ru`…`v5_6_ru`. Лечилось обновлением кэша, не pip. Новый id по-прежнему надо сверять с `models.yml`.
2. Побуквенная транслитерация всего текста до конвертации цифр (старый `txtproc.py`) превращала URL и даты в кашу. Поэтому URL/IP/даты идут первыми, латиница — последней.
3. `\b` после `%` в regex не срабатывает (`%` — не word-char). У единиц стоит `(?!\w)`.
4. Устройство выбирается само: CUDA есть — `cuda`, нет — `cpu`. Старый комментарий «на GTX 1080 лучше CPU» убран. Принудительный CPU — `SILERO_DEVICE=cpu`.
5. Скорость нельзя крутить сменой `sample_rate` или `ffplay -af atempo`: первое — частота файла, второе растягивает уже готовый WAV. Актуальный путь — CLI `1`–`5` → SSML.
6. `ffplay` с ненулевым кодом больше не валит весь прогон: WAV к этому моменту уже записаны, скрипт предупреждает и выходит 0. Провал синтеза — это `exit 2` от `silero10.py`, до `ffplay` дело не доходит.
7. Репозиторий git в домашнем каталоге не заводился: рядом с пайплайном лежат посторонние файлы и ключи. Каталог проекта из `$HOME` не переносился.
8. Прошлый результат больше не уничтожается до первого успешного фрагмента: синтеза предшествует staging, а `rm -f out_*.wav` из начала прогона убран. Прежний проигрыш — прогон падал на загрузке модели (cuDNN, OOM) или на битом `input.txt`, и в `silero_output/` оставалось ноль файлов. Теперь при любом ненулевом коде `txtproc.py`/`silero10.py` рабочий каталог остаётся в состоянии «как до запуска», а `list.txt` не переписывается. Подмена несовершенна: между двумя `mv` есть окно, в котором `silero_output/` лежит в `.old`, так что параллельный запуск `ffplay` в этот момент ничего не найдёт.
9. Ошибки входа больше не traceback: отсутствие файла и файл не в UTF-8 — одна строка в stderr и `exit 1` (подробности — «Ошибки входа» выше). Если `input.txt` прислан в Windows-1251 или UTF-16, сообщение об этом укажет байт и позицию; лечится `iconv -f WINDOWS-1251 -t UTF-8 input.txt`. Проверить кодировку заранее: `iconv -f UTF-8 -t UTF-8 input.txt > /dev/null && echo UTF-8`.
10. CUDA 11 и CUDA 13 в env `silero` лежат в одном каталоге `site-packages/nvidia/cudnn/lib/`. Работает, пока правки ставятся целиком через `requirements.txt`; выборочное удаление пакетов CUDA 13 ломает `import nvidia.cudnn` в `play.sh`. Разбор и симптомы — «CUDA 11 и CUDA 13 в одном env» выше.
11. `ffplay` на битом или недоступном WAV возвращает **0** — «отыграло» неотличимо от «молчало». Лечится предпроверкой `probe_first_last` (шаг 12 разбора `play.sh`): `ffprobe` первого и последнего файла из списка, предупреждение в stderr, код возврата прежний. Это не проверка всех файлов каталога: середина склейки остаётся непроверенной.
12. `--resume` опирается на нумерацию `out_NNNN.wav`, а она зависит от нарезки. Правка в `chunking.py` (или в правилах `txtproc.py`, меняющих длину фраз) сдвигает номера, и «готовые» файлы начинают соответствовать другим фразам: прогон с `--resume` оставит старые WAV там, где им уже не место. После таких правок первый прогон делают без `--resume`.
13. Громкость: Silero пишет пик впритык к 0 dBFS, и в PCM_16 это клиппинг (D12). Справляется `normalize_peak` с запасом `HEADROOM_DB = -1` dBFS. Правка меняет амплитуду, но не среднюю громкость: после неё тихие и громкие фрагменты могут звучать ровнее, чем раньше; полное отключение — `SILERO_HEADROOM_DB=0`.
14. `--log` требует терминала: при перенаправленном stdout (`./play.sh --log f > out.txt`) флаг отклоняется с `1`, а не пишет вывод в две места молча. Причина — `tee` физически не может вернуть уже переназначенный поток в терминал.
